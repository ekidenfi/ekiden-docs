This section describes the REST endpoints and corresponding TypeScript SDK methods for retrieving user account information, balances, positions, executions, and account statistics.

## REST Endpoints

| Resource | Endpoint |
| --- | --- |
| Root Account | `GET /api/v1/user/root-account` |
| Sub Accounts | `GET /api/v1/user/sub-accounts` |
| Positions | `GET /api/v1/position/list?sub_account_address=<address>` |
| Executions (Fills) | `GET /api/v1/execution/list?sub_account_address=<address>` |
| Account Balances | `GET /api/v1/account/balance` |
| Account Statistics | `GET /api/v1/account/statistics` |

## TypeScript SDK

Retrieve the authenticated user's root account:

```ts
const rootAccount = await client.user.getRootAccount();
```

Retrieve all sub-accounts:

```ts
const subAccounts = await client.user.getSubAccounts();
```

Retrieve account balances:

```ts
const balances = await client.account.getBalance();
```

Retrieve positions:

```ts
const positions = await client.position.getPositionInfo({
  sub_account_address,
});
```

Retrieve execution history:

```ts
const executions = await client.trade.getTradeHistory({
  sub_account_address,
});
```

Retrieve account statistics:

```ts
const statistics = await client.account.getStatistics({
  sub_account_address,
});
```

## Balance fields

`GET /api/v1/account/balance` and the `account_balance` WebSocket topic return one entry per account. Amounts are USDC decimal strings unless noted. The fields that reflect [multi-asset collateral](/collateral):

| Field | Description |
| --- | --- |
| `vault_balance` | Quote (USDCx) balance. Shows `0` while there is a `debt`. |
| `equity` | What the account is worth to liquidation, floored at zero: the quote balance (a debt counted in full), unrealized P&L and funding, and unfrozen collateral at its maintenance weight. |
| `margin_balance` | Same as `equity`. |
| `collateral[]` | Non-quote collateral; omitted when there is none. See below. |
| `initial_total_collateral` | Quote balance, unrealized P&L, funding, and non-quote collateral at its initial weight. Trading accounts holding non-quote collateral or owing a debt only. |
| `maintenance_total_collateral` | The same total at maintenance weight, collateral on hold excluded. Present when `initial_total_collateral` is. |
| `debt` | Quote owed: how far the quote balance is below zero. Omitted when nothing is owed. |
| `fee_asset` | The first asset other than the quote in `fee_priority`. Trading accounts only. |
| `fee_priority[]` | The assets fees are taken from first, in order. Trading accounts only; omitted while empty. See [Fee Asset](/api-reference/integration/fee-asset). |

Each `collateral[]` entry:

| Field | Description |
| --- | --- |
| `asset_id`, `symbol` | The asset, as in `GET /api/v1/collateral/assets`. |
| `balance` | Whole tokens, including the amount on hold. |
| `frozen` | Whole tokens on hold for a withdrawal. |
| `price` | USDC per token. Trading accounts only. |
| `initial_weight`, `maintenance_weight` | Effective weights: `initial_weight` is `"0"` unless the asset is active and freshly priced. Trading accounts only. |
| `initial_value`, `maintenance_value` | Value at each weight, in USDC. Trading accounts only. |

## Execution fee fields

Executions (REST and the `execution` WebSocket topic) carry how each fill's fee was paid:

| Field | Description |
| --- | --- |
| `fee` | Signed fee in raw quote units (negative is a maker rebate). Empty on fills recorded before fees were stored. |
| `fee_asset` | The asset that paid the fee; omitted when it is the quote. |
| `fee_legs[]` | When the fee was split across assets: `{asset_id, amount, quote_equivalent}` per asset. |
| `seized_legs[]` | On liquidation takeovers only: `{asset_id, amount, quote_credited}` per collateral asset seized. |

<Warning>
  These fields are **raw integer units**, unlike the decimal strings elsewhere. `fee`, `quote_equivalent` and `quote_credited` are in the quote's units: divide by `10^decimals` of asset `1`. Each leg's `amount` is in its own asset's units: divide by that asset's `decimals`. Both come from `GET /api/v1/collateral/assets`.
</Warning>

## Timestamp Fields

REST resources use Unix timestamps in milliseconds.

Common timestamp fields include:

- `created_time`
- `updated_time`
- `timestamp_ms`

Some legacy responses may still include the `timestamp` field for backward compatibility.
